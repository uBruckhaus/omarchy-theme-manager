# Theme Manager

Every Omarchy theme, user and system, in one popup: apply, favorite, hide or delete it, and manage the wallpapers that come with it or that you add. Make your own themes from any theme or any picture, give every workspace its own wallpaper, and every theme its own key.

![Theme Manager](preview.png)

## Features

- **All themes in one place.** User themes (`~/.config/omarchy/themes/`) and system themes (`/usr/share/omarchy/themes/`) in a single scrollable list, each with a large preview and badges for current/system/hidden themes.
- **Apply a theme** from its ⋮ menu.
- **Hide themes** from the list via the ⋮ menu. Hidden themes stay installed; the eye button in the header shows them again (dimmed) so you can unhide them. Hidden state is stored in `~/.config/omarchy/theme-manager/hidden.json`. Applying a hidden theme, from Theme Manager or with `omarchy theme set`, unhides it automatically. The theme you are using always stays in Omarchy's picker, even while hidden; otherwise a picker with every theme hidden would be empty, and Omarchy's picker shows its last full list instead of an empty one.
- **Optionally hidden in Omarchy's pickers, too.** Off by default. Switch on **Settings (⚙) → Also hide in Omarchy's pickers** and hidden themes also leave Omarchy's own theme switcher (Menu → Style → Theme), hidden wallpapers its background picker. Unhiding brings them back. See *Syncing with Omarchy's pickers* below.
- **Make your own themes.** **New theme from this…** in any theme's ⋮ menu opens an editor: give it a name, pick the colors (background, text, accent, selection, muted text, the eight terminal colors, and under *More colors* every shade and bright variant) with a color picker or as `#rrggbb`, and choose a font. A sample window shows the result as you go. The base theme's wallpapers are copied over (you can switch that off) and can be changed later on the new theme's wallpaper page like in any of your themes. **Edit theme…** changes a theme made this way again: its name (renaming keeps its wallpapers, favorites, workspace wallpapers and day/night choices), colors and font; saving the theme you are using applies it right away. Omarchy builds every app's colors (terminals, editors, the bar, Hyprland borders, …) from the colors you pick.
- **A theme from a wallpaper.** **New theme from this wallpaper…** in a wallpaper's ☰ menu takes the colors from the picture: the background in its main hue (dark, or light for bright pictures), the accent from its most vivid color, and every terminal color from the picture's own shade of that hue where it has one, at one lightness so all stay readable. The editor opens with those colors and the name of the picture, ready to adjust; the new theme gets that wallpaper (and, if you like, the base theme's others).
- **Font & effects per theme.** Omarchy has one monospace font for the whole system (Menu → Style → Font) and one window style (Menu → Style → Windows: opaque, transparent or glassy, where glassy blurs what is behind see-through windows, the bar and menus). **Font & effects…** in any theme's ⋮ menu (system, imported or your own) gives that theme a font and a window style of its own, each *Theme default* or a value; the theme's files stay as they are, the choice is kept in `looks.json`. Applying the theme switches to them, and applying a theme without them gives you back the font and window style you had before. A theme you made can also remember a font in its editor (the Font & effects choice wins over it). **Apply** is enabled once something changed and saves it; for the theme in use it also puts the change on the desktop right away. If its font or window style was changed elsewhere, its ⋮ menu offers **Reapply**. Undo is offered after each change. The window style needs Omarchy 4.5 or later (`omarchy-hyprland-window-transparency`); without it only the font is shown.
- **Favorites and recently used.** ★ a theme in its ⋮ menu and it is listed first, and offered when you right-click the bar icon. Settings (⚙) can also sort the rest by when you last used them.
- **Delete user themes** after an explicit confirmation. They go to the trash (the same one your file manager uses), and **Undo** (or Ctrl+Z) in the popup brings them back for a few seconds afterwards. Wallpapers you added to the theme are kept. The active theme cannot be deleted: apply another theme first. Only themes in your own themes directory can be deleted; system themes are root-owned and read-only here — hide them instead.
- **Wallpapers per theme.** Open a theme's wallpaper page to see what it ships. Add your own by **drag & drop** of image files from the file manager or of pictures straight from a web page, or by **pasting** (Ctrl+V) an image copied in the browser or a file copied in the file manager. iPhone photos (HEIC) are converted to JPEG. Each wallpaper's ☰ menu can set it as the background (current theme), **hide** it, or **delete** it. Added wallpapers are stored in `~/.config/omarchy/backgrounds/<theme>/`.
- **Add wallpapers with a file chooser.** The first tile on a wallpaper page, **Add wallpapers…**, opens a file chooser in `~/Pictures` (the popup steps aside while it is open). It is also where pictures go: drop them anywhere on the page (the tile lights up) or paste them with Ctrl+V.
- **Preview before you decide.** Hold **Space** on a wallpaper (or on a web search result) and it shows on the desktop until you let go; **Preview on desktop** in its ☰ menu shows it for five seconds. Your background is not changed.
- **A wallpaper for each workspace.** In a wallpaper's ☰ menu, **Show on workspace…** picks workspaces 1–10. Whenever you switch to one, its wallpaper fades in; other workspaces keep the theme's background. Assignments belong to a theme, so every theme can have its own set. Tiles show their workspaces (`ws 2 · 5`).
- **A theme for each workspace.** A theme's ⋮ menu offers **Use on workspace…**. On focus, Theme Manager switches Omarchy's global theme to the assigned one. This changes the theme on every monitor. An unassigned workspace returns to the theme in use before the assignment. The feature is off until an assignment is made or enabled in Settings → Wallpapers; existing wallpaper-only assignments continue to work. The current theme's menu also offers **Use on all workspaces** while any workspace has a theme of its own: the assignments are removed and the current theme is used everywhere (with Undo, as long as nothing changed meanwhile), until the next day/night switch; workspace wallpapers stay.
- **Presets.** The bookmark icon in the header opens the Presets page with three tabs (Workspaces, App Presets, Save/Load Presets):
  - **Workspaces** (the same feature as the Workspace Presets plugin, which stays its own plugin): a card per workspace with a picture of its layout, in two groups (**Workspaces 1–5** and **Workspaces 6–10**, with **All Workspaces** in both) so the chosen workspace's controls stay in view below; in a wide popup the cards and, below them, the chosen workspace's controls (each section in its own group card) fill the left; the right shows the chosen workspace large as it looks, fading over when you pick another card. On that preview you can drag: a layout choice onto it to use that layout (the default for All Workspaces), one window onto another to swap them (the saved places of an App Preset, or the real windows of the workspace), and its right edge (the gap beside the windows) to set the window limit (1–4). While a window is dragged, a row of drop targets appears along the bottom of the preview: every layout for the window limit (the current one checked) and "− 1 window"; the master window dragged over the others moves it to that side (Master Left ↔ Master Right), the line between the windows of Master Left/Right, Side-by-Side or Stacked sets their sizes (20–80 %, double-click for even, `[` and `]` in 5 % steps; sent to Hyprland as the master share or split ratio), and one dragged out of the preview means one window fewer. The **+** at the right edge of the preview adds a window: a click raises the limit by one, dragging it into the preview also chooses the layout by where you drop it (the sides: Master Left/Right, the middle: Columns, a corner: 2×2 Grid, top/bottom for two windows: Stacked) – it sets the layout, Hyprland still decides where the next window opens. Columns with three windows has two lines around the middle column; either sets its width (20–60 %, sent as the master share). On an App Preset, **+** adds an app from your launchers to the preset (dropped on a window it halves that one, else the largest; it is only saved, **Restore App Preset** starts it), the edge two saved tiled windows share moves both of them, and a saved floating window has a corner handle for its size; these change the saved positions that Restore applies. The large preview over the narrow popup works the same way and stays open while you change things in it. A label shows the exact result while dragging, Esc cancels, and every change offers Undo (also Ctrl+Z). Keyboard: Tab to the preview, ←/→ choose a window, Shift+←/→ swap it, + and − change the limit. In the narrow popup the magnifier on a card fades its small picture out and opens a large preview over the popup: the workspace as it looks, with its wallpaper, the theme's colors and the windows of its layout (the active one with the accent border). A click anywhere or Esc closes it. **All Workspaces** holds **Tiling active** (window limits with overflow, off until you turn it on), the default window limit (1–4), the default layout per limit and the bulk actions (reset all, remove all presets, clear everything). A workspace card sets its own limit and layout: Side-by-Side, Stacked, Master Left/Right, Columns, 2×2 Grid, Native, Floating or Scrolling (with Omarchy 4.5 the last two are the workspace's Omarchy mode, the one Super + L cycles). New windows that don't fit move on to the next workspace with room; moving windows by hand always wins.
  - **App Presets:** save the open windows of a workspace where they are, restore them (missing apps start from their installed launcher; windows that don't belong are moved, closed or kept floating, as you choose, or always moved with **Auto-move on restore**), remove single apps, and start them automatically once per login.
  - **Save/Load Presets** (last tab): save the current theme and wallpaper under a name (the theme brings its own font and window style through Font & effects), apply it later, or assign its theme, wallpaper or both to workspaces 1–10. A preset records references to installed themes and wallpapers, so moving or deleting those files makes that part unavailable. **Include workspace presets and app presets** also saves the two tabs below with it; applying such a preset lays the workspaces out again and restores its App Presets (missing apps start, other windows on those workspaces move to a free one, so Theme Manager asks first).
  Without the Workspace Presets plugin the settings live in `~/.config/omarchy/theme-manager/workspaces.json` (the first time taken from that plugin's bar entry, if there is one). While the plugin is on the bar, both share one set of settings, its own bar entry in `~/.config/omarchy/shell.json`: Theme Manager reads and edits that entry (only the workspace keys; it keeps `workspaces.json` as a copy), the plugin moves the windows and Theme Manager doesn't (never both). A note above the Presets tabs says so. The bar widget listens for new windows and runs `workspace_tiling.py` (moved here from that plugin) one window at a time.
- **Wallpaper slideshow.** Settings (⚙) → **Change the wallpaper** every 5 minutes to 2 hours, through the current theme's visible wallpapers. Workspaces with their own wallpaper keep it.
- **Day and night themes.** Pick a day and a night theme (in Settings, or **Use as day/night theme** in a theme's menu) and the times they start. Theme Manager switches at those times; a theme you pick by hand in between stays until the next switch.
- **Find settings quickly.** Settings has a section sidebar and a search field, like Maprisma Launcher. On narrow screens, the sidebar becomes a row of section buttons. Choose General, Themes, Day and night, Wallpapers, Keyboard shortcuts or Screenshots; searching shows matching rows across sections.
- **Ask AI** (off by default; Settings → Ask AI, or **Turn Ask AI on** on its page). The sparkle in the header (as in Maprisma Launcher: accent when a helper is ready, a dot while none is signed in, dim while off) opens a page; with Claude Code, Codex, pi or Hermes installed and signed in, or a local model, where you describe what you want — “blue borders, red text and a nice dog wallpaper”, “another font for Kanagawa”, “a warm dark theme from the catalog”. The suggestions under the field sit in a card, one row each (two rows in a narrow popup, four in a wide one; the rest scrolls), and are yours to shape: the bookmark button next to **Ask** saves what you typed as a new one (up to 12), ⠿ drags a row to another place (or Alt+↑/↓; Esc cancels a drag), ✎ edits one in place (Enter saves, Esc cancels), × removes it, and ↺ brings back the built-in ones. One click on **Ask** sends one request (your plan or tokens, only then) and shows up to three candidates as they would look: a large preview in their colors with a wallpaper from the wallhaven search (‹ › for the next picture, no tokens), their eight terminal colors and font. **Use** opens the theme editor filled in (nothing is saved until you save; a system theme is never changed, you get a copy) or, for an omarchy.org theme, its install menu; **Not this** drops one; **Refine…** sends only that candidate and your words back. The agent runs without tools (Claude Code, pi, Hermes) or in a read-only sandbox (Codex), in an empty private folder; it gets the installed themes' main colors, the catalog's theme names and the installed fonts, with your text marked as data. Its answer is checked before anything is shown: only existing themes, known color keys as #rrggbb (text kept readable), installed fonts, and a search phrase instead of any URL. File paths, wallpapers, screenshots, window titles and settings are never sent. **Local models:** every local chat model pi is connected to (`~/.pi/agent/models.json`, a provider on localhost such as llama.cpp or Ollama) is a helper of its own, marked *on this PC*; pi runs it with `--offline`, and Hermes counts as local when its default model is. They use no tokens and nothing leaves the computer; if their server is not running, Theme Manager starts `llama-server.service` (port 8080) or `ollama.service` (port 11434) as a user unit and waits for it. pi runs without tools, MCP servers, extensions or project files, Hermes with only its in-memory task list. The microphone beside the field (and beside **Refine…**) lets you speak the request instead of typing; it works like Omarchy's dictation key: it puts the cursor in the field and runs `omarchy-dictation toggle` (the backend chosen in Setup › Defaults › Dictation, e.g. Superwhisper), which starts dictation or stops it when it runs, writes what you say at the cursor and shows its own recording indicator. With no dictation program set up yet, a click on the microphone explains how (Setup › Defaults › Dictation) and can open that menu; away from Omarchy there is no microphone. In Settings and on the Ask AI page a small ? next to the helper opens a note on **Maprisma** (easy AI setup for online and local agents and providers) with a link to its page in the Omarchy Plugin Marketplace; **Settings → Ask AI → Maprisma hints** (on by default) removes the ? and the note.
- **F12 screenshot.** F12 saves a picture of the popup in `~/Pictures/ThemeManager/` or another folder you choose (Settings → Screenshots, where the key can also be turned off). It is on by default, as in Maprisma Launcher. A small dialog then shows where the picture went and asks “What is wrong? (optional)”: Done or Enter saves the note as a `.txt` beside the picture (no note, no file), Esc skips it (closing the popup keeps a note already typed), and Open folder shows the folder. Only F12 alone counts (not with Shift, Ctrl, Alt or Super); it also works while you type in a field or a pop-up list is open. F12 remains available when assigning a theme shortcut on the shortcut capture page.
- **Sync health and backup.** Settings → Integration and backup shows whether the Omarchy picker integration is ready and offers a repair action. Export saves settings, lists, workspace assignments, presets, workspace presets and App Presets, Font & effects, and shortcuts as dated JSON (saved terminal commands of App Presets are dropped on restore; those apps start from their launcher). Restore confirms what will be replaced and saves a timestamped copy of the current state in `~/.config/omarchy/theme-manager/backups/` first. Theme and wallpaper files stay in their own folders and are not included.
- **From the bar.** Scroll on the paint-brush icon for the next or previous wallpaper; right-click it for your favorite themes (or the recently used ones), the next wallpaper, and Theme Manager itself.
- **Resizable and movable.** Drag the grip in the bottom-right corner to resize, the title bar to move. Themes are tiles: two columns already at the default width (each showing its name, badges and shortcut), up to four that grow with the window when it is wider, like the wallpaper, web search and import pages. In a wide popup the theme editor shows its sample large on the left of the colors. **Double-click the title bar**: at the default size either mouse button maximizes, maximized either one goes back to the default size; in between, left goes back to the default size and right maximizes (both centred). A small hint in the header says what a double-click does right now. Double-clicking the grip also restores the default size. Size and position are remembered.
- **Hidden wallpapers** (with the Omarchy sync on) leave Omarchy's background picker, *next background* and the background chosen on theme switch. The files stay where they are, so hiding works for every wallpaper. If the hidden one is on the desktop, the next visible one takes its place. The last visible wallpaper of a theme cannot be hidden.
- **Search wallpapers on the web.** On a theme's wallpaper page, **Search the web** (Ctrl+F) searches [wallhaven.cc](https://wallhaven.cc) for whatever you type: safe-for-work landscape images of at least 1920×1080, with more results as you scroll. A result's ☰ menu adds it to the theme, adds it and sets it as the background (current theme), or opens its page in your default browser.
- **Import themes from [omarchy.org](https://omarchy.org/themes/)** (download button in the header, or Ctrl+I): the whole gallery with previews and search. A theme's ☰ menu installs it, installs and applies it, or opens its GitHub page in your default browser (a hint appears if none is set).

## Deleting versus hiding wallpapers

| Wallpaper | Delete (to the trash) | Hide |
| --- | --- | --- |
| Added by you (`~/.config/omarchy/backgrounds/<theme>/`) | yes | yes (moved to `.hidden/` inside that folder) |
| In a theme you created yourself | yes | yes |
| In a theme installed from git | no: `omarchy theme update` runs `git pull`, which a deleted file would break | yes |
| In a system theme (`/usr/share/omarchy/themes/`, owned by root) | no: needs root, and the next Omarchy update restores it | yes |

Theme Manager never asks for root. Shipped wallpapers are hidden by name in `~/.config/omarchy/theme-manager/hidden-wallpapers.json` and removed only from Omarchy's per-user copy of the current theme (`~/.local/state/omarchy/current/theme/backgrounds/`), which `omarchy theme set` rebuilds on every switch. With the Omarchy sync on, a theme-set hook (`~/.config/omarchy/hooks/theme-set.d/90-theme-manager`) re-applies the hidden list after each switch.

## Languages and settings

The interface is built in in eight languages: English, German (Deutsch), French (Français), Spanish (Español), Italian (Italiano), Portuguese (Português), Dutch (Nederlands) and Polish (Polski). It follows the system language (`LC_ALL`, `LC_MESSAGES`, `LANG`) and falls back to English. To pick another one, open the **gear (⚙)** at the top right of the panel → **Language**. The translations ship with the plugin: nothing is downloaded or generated, and the plugin makes no extra requests for them. The choice is stored in `~/.config/omarchy/theme-manager/settings.json` (`"language"`); the bar icon's tooltip and right-click menu follow it too; **System (…)** removes it again.

The settings page opens from the gear and closes with **← Back**, Backspace or Esc. Switching the language restarts the popup on the settings page, so every label is rebuilt.

The **ⓘ** button beside the gear opens an **Information** page with a card for each of the author's other plugins in the Omarchy Plugin Marketplace, with a short description in the panel's language. A click on a card opens that plugin's marketplace page in the browser (a fixed `https://plugins.omarchy.org/plugin.html?id=…` address). The list comes from the marketplace's catalog, so newly published plugins of the author appear without a Theme Manager update; a plugin this version does not know yet shows the first sentence of its marketplace description, in English (see *Privacy and capabilities*). **← Back**, Backspace or Esc returns.

## Install

```sh
omarchy plugin add https://github.com/uBruckhaus/omarchy-theme-manager.git --enable
```

A paint-brush button appears in the bar. Click it to open or close the popup. The popup stays running in the background between opens so it appears instantly; it holds no data of its own.

The popup is a floating card that stays open while you work in other windows, so you can drag pictures into it: only the bar icon or **Esc** closes it. Drag its title bar to move it (the position is remembered), double-click the title to bring it back to its default size, centered; drag the grip in the bottom-right corner to resize it. The keyboard follows the mouse, as everywhere in Omarchy.

### Keyboard shortcuts

Set keys in **Settings (⚙) → Keyboard shortcuts**: **Open Theme Manager**, **Next wallpaper**, **Previous wallpaper** and **Next favorite theme** (cycles through your ★ themes). Every theme can have its own key too: its ⋮ menu → **Shortcut…**; the key then applies that theme from anywhere, and the theme shows it in the list. A theme's key also works while the theme is hidden (applying it unhides it, as always). When you delete the theme, its key is removed once Undo is no longer offered, and the key, or the binding it had taken over, works as before. A key whose theme was deleted outside Theme Manager says so when pressed and is removed then.

The shortcut page works like Launch & Bind's: hold the modifiers and press a key, or toggle Super/Shift/Ctrl/Alt and click a key. Every letter, digit and the other keys are coloured by who has them: green free, yellow one of your bindings (or another Theme Manager key), orange an Omarchy default. A taken key can be **Rebind**-ed: the original binding is turned off only while your shortcut exists, and **Remove** gives it back. While the page is open, Hyprland is switched to an empty submap so even bound combos reach the page (Super + Escape leaves it should anything go wrong).

Keys are kept in `~/.config/omarchy/theme-manager/shortcuts.json` and written to `~/.config/hypr/theme-manager-shortcuts.lua`, which a marked line at the end of `~/.config/hypr/hyprland.lua` requires (a backup is kept as `hyprland.lua.before-theme-manager-shortcuts`). Your own files are never edited otherwise. Every change is checked with `hyprctl configerrors` and rolled back if Hyprland rejects it. Removing the last shortcut deletes the generated file and the marked line again.

## Use

1. Click **Theme Manager** in the bar. The list shows every installed theme; your current theme is marked.
2. **Click a theme row** to open its wallpaper page.
3. **⋮ menu** on a row applies the theme, opens its wallpapers, adds it to your favorites, makes it the day or night theme, hides or unhides it, or deletes it (user themes only, with confirmation). The popup stays open afterwards, so you can apply or delete several themes in a row; applying also restyles the popup in the new theme's colors.
4. **Eye button** in the header shows or hides the themes you have hidden.
5. On the **wallpaper page**, drag image files from the file manager or pictures from a web page (tested with Chrome, Chromium and Vivaldi) onto the popup, or paste with Ctrl+V an image copied in the browser ("Copy image") or a file copied in the file manager, to add wallpapers to that theme. HEIC photos are converted to JPEG (needs libheif's `heif-dec`). ✕ removes a wallpaper you added.
6. **Keyboard**, as in Simple Launcher: ↑/↓, Page Up/Down, Home/End select a theme; **Enter** opens its wallpapers; **→** (or the Menu key) opens its action menu, **←** or **Backspace** closes it. On the wallpaper and import pages the arrows move between tiles, **Enter** opens a tile's menu (on **Add wallpapers…**: the file chooser), holding **Space** previews a wallpaper on the desktop, and **←** (from the left column), **Backspace** or **Esc** go back. **Ctrl+Z** undoes a delete while Undo is offered. On the import page, typing searches. **Type to filter**, as in Simple Launcher: typing on the theme list or a wallpaper page filters it by name (the title shows the filter, Backspace removes a character, Esc clears it). **Ctrl+I** opens the import page, **Ctrl+F** on a wallpaper page opens the web search (Enter searches, ↓ moves into the results); Esc on the list closes the popup.

## Settings (⚙)

| Setting | What it does | Default |
| --- | --- | --- |
| Language | Interface language: the system's, or one of the eight built-in ones | System |
| Corners | The corners of the popup, its cards and every control: **Like windows** follows Hyprland's window rounding (set by the current theme's `hyprland.lua` or your `~/.config/hypr/looknfeel.lua`; the tooltip says which), **Slightly rounded** (6 px), **Rounded** (12 px) or **Square**. One setting in three sizes, as in AI Playground: the popup, cards, dialogs, pop-ups and previews take the full radius; buttons, drop-downs, fields and search fields at most 8 px; check boxes, slider tracks, badges and colour swatches at most 4 px; chips and switches are pills. The drawn workspace pictures follow it too, and **Square** makes everything square, tooltips and GTK's own controls included | Like windows |
| Sort the list | By name, or recently used first (favorites always come first) | By name |
| Also hide in Omarchy's pickers | See *Syncing with Omarchy's pickers* below | Off |
| Switch themes by time of day | Day theme from one time, night theme from another | Off |
| A wallpaper for each workspace | Shows the wallpapers picked with **Show on workspace…** (switched on by the first pick) | Off |
| Change the wallpaper | Slideshow through the current theme's visible wallpapers | Never |

**Reset to defaults** (bottom left of the settings page) sets: system language, corners like the windows, sorted by name, Omarchy sync on, no day/night switching (07:00 / 19:00), a wallpaper for each workspace on, the wallpaper never changes. Shortcuts, favorites, hidden themes and the chosen day and night themes stay.

Up to 1.5 the popup always had 12 px corners (it misread Hyprland's rounding); pick **Rounded** to keep that look.

Workspace wallpapers, the slideshow and day/night switching are run by the bar widget, which is part of the Omarchy shell anyway: it calls `theme_auto.py` when you switch workspaces (only while workspace wallpapers are on) and once a minute (only while the slideshow or day/night switching is on). Nothing runs when they are off. Backgrounds are set with Omarchy's own `omarchy-theme-bg-set` and themes with `omarchy theme set`, so Omarchy's pickers stay in step.

## Syncing with Omarchy's pickers (opt-in)

Off until you switch it on in **Settings (⚙)**. Without it, hiding applies to Theme Manager's own lists only and Theme Manager writes nothing into Omarchy's files. When you switch it on:

Omarchy's theme picker shows one preview per theme from its cache in `~/.cache/omarchy/theme-selector/previews/`. Theme Manager keeps hidden themes out of it:

- Hiding a theme removes its preview link from that cache (only the link; no theme file is touched). Unhiding asks Omarchy to rebuild the cache.
- Theme Manager points the menu's **Theme** entry at its `theme-switcher` wrapper by adding one marked line to `~/.config/omarchy/extensions/omarchy-menu.jsonc`. The wrapper runs Omarchy's unchanged `omarchy-theme-switcher` and drops hidden themes again whenever Omarchy rebuilds its cache. If you already override `style.theme` yourself, your entry is left alone.

Deleting or installing a theme changes the theme folders, which makes Omarchy rebuild that cache. Theme Manager rebuilds it right away through the wrapper, and the theme-set hook does the same after `omarchy theme install`, so Omarchy's own rebuild finds nothing to do and hidden themes stay hidden.

- It installs the hook `~/.config/omarchy/hooks/theme-set.d/90-theme-manager`, which re-applies hidden wallpapers and the theme filter after every `omarchy theme set`.
- On Omarchy 4.5 and later, the built-in picker keeps its own theme rows in the shell and calls the stock switcher directly. Two seconds after the bar starts, Theme Manager refreshes the filtered cache and asks that picker to reload its rows. This also runs after a shell restart. Older Omarchy versions keep using the menu wrapper and theme-set hook above.

**Switching it off** removes exactly the marked menu line and the hook again, and lets Omarchy rebuild its pickers with everything. `omarchy plugin remove` does not run plugin code, so switch the sync off *before* removing the plugin (or delete the two lines below `// theme-manager:` in that file and the hook by hand).

## Remove

```sh
omarchy plugin remove ubruckhaus.theme-manager
```

This removes the bar button and the popup. Your themes and the wallpapers you added are **not** touched. If you had switched on the Omarchy sync, switch it off first (Settings ⚙), or afterwards remove the marked lines in `~/.config/omarchy/extensions/omarchy-menu.jsonc` and `~/.config/omarchy/hooks/theme-set.d/90-theme-manager`. To also drop Theme Manager's own state and caches:

```sh
rm -rf ~/.config/omarchy/theme-manager ~/.cache/theme-manager ~/.cache/ubruckhaus.theme-manager
```

## Privacy and capabilities

- Never asks for root or administrator rights; no bundled binaries.
- Network access only for **Import themes**, **Search the web** and the **Information** page (all three below). **Import themes** contacts only `https://omarchy.org` (the gallery page and its preview images), and **Search the web**, which contacts only Wallhaven: the search API on `wallhaven.cc`, thumbnails on `th.wallhaven.cc` and images on `w.wallhaven.cc`. Every address in an API reply must match its exact expected shape, the safe-for-work filter is fixed, and your search text is only a URL-encoded query parameter. Both go through `curl` with HTTPS only, no redirects, and a size and time limit on every request. The theme list is cached for a day in `~/.cache/theme-manager/`, and at most 400 wallpaper thumbnails in `~/.cache/theme-manager/wallhaven/`. Installing runs `git clone --depth 1` of the theme's link, which must exactly match `https://github.com/<owner>/<repo>`, after Omarchy's own `omarchy-git-url-check` where Omarchy has it (4.0.1 and later; 4.0.0 relies on the exact match alone, which already rules out every git transport helper), without prompts, into `~/.config/omarchy/themes/<name>`. An existing theme is never replaced. Theme pages open with `omarchy-launch-browser`.
- The **Information** page (ⓘ) reads the marketplace's catalog `https://raw.githubusercontent.com/omacom/omarchy-plugin-marketplace/main/site/catalog.json` when it is opened (on a worker thread; a request in progress finishes even if you leave the page) through `curl --proto =https --max-redirs 0` (at most 40 MiB and 40 s; the reader stops at 40 MiB + 64 KiB and 45 s), with the last `ETag`, so an unchanged catalog is not downloaded again (a list cached before 1.8.1, when only `github.com/ubruckhaus` counted, is read once more in full without it), at most once an hour, failed attempts included (kept in the cache; if the cache cannot be written, only for as long as the popup keeps running). Only the author's own entries (repositories under `github.com/ubruckhaus` or `github.com/maprisma`, at most 60) are kept, as id, name, version, description text and the verified flag, with the time of the last check and the `ETag`, in `~/.cache/ubruckhaus.theme-manager/plugin-catalog.json` (the folder must be yours, not a link and closed to others — it is made `0700` if missing, otherwise nothing is read or written; file `0600`, written atomically inside that folder; read back only as a regular file of yours, at most 1 MiB). The names and texts are shown as plain labels; a card opens only the fixed marketplace address. No themes, wallpapers, settings or other local data are sent; GitHub sees the usual request details (your public IP address, the fixed user agent and the `ETag`). Offline, the cached list or the built-in one is shown.
- Runs `omarchy theme …`, `omarchy-theme-bg-set`, `omarchy-shell -q background set`, `omarchy-font-list/-current/-set`, `omarchy-hyprland-window-transparency` and `hyprctl` as argv subprocesses without a shell; every subprocess read is size- and time-bounded. HEIC photos are copied into a private temporary directory and their declared sizes (every image extent and the canvas of tiled "grid" photos) are read from the file's `meta` box first; anything over the decoded-image limit below is refused before libheif runs. The conversion then runs `heif-dec` under `prlimit --as=2GiB --fsize=50MiB`, so the decoder's memory and every file it writes are capped as well.
- While the popup is open it also listens on Hyprland's event socket (`$XDG_RUNTIME_DIR/hypr/<instance>/.socket2.sock`, read-only, bounded): when one of Omarchy's own menus or panels opens (Super + Space, the clipboard, emoji or image pickers), Walker or App Manager, the popup closes, so that menu gets the keyboard at the first press. Nothing from that socket is executed or shown. The Super key alone does nothing, so Super + drag still moves windows.
- While you drag the popup by its title bar, and for a moment after opening, it reads the cursor position from Hyprland's own IPC socket (`$XDG_RUNTIME_DIR/hypr/<instance>/.socket.sock`, the one `hyprctl` uses): one read-only `cursorpos` request, size-capped with one overall deadline.
- Reads and writes under `~/.config/omarchy/` (themes, backgrounds, `theme-manager/` state, and, only with the opt-in Omarchy sync on, one marked line in `extensions/omarchy-menu.jsonc` and the hook `hooks/theme-set.d/90-theme-manager`) and `~/.cache/theme-manager/` (plus `~/.cache/ubruckhaus.theme-manager/` for the Information page), plus the trash (`~/.local/share/Trash/`) for deletes. F12 writes a PNG (`0600`) to `~/Pictures/ThemeManager/` or the folder you choose (it must be yours and closed to others; `grim` writes into a new private folder first, the copy is created exclusively and never follows a link); it calls `grim` locally and sends no screenshot over the network. It removes preview links in `~/.cache/omarchy/theme-selector/previews/` and hidden wallpapers from Omarchy's copy in `~/.local/state/omarchy/current/theme/backgrounds/`. System theme files are never modified.
- Workspace presets and App Presets: `workspace_tiling.py` talks to Hyprland through `hyprctl` (moving, resizing and closing windows only as described above), reads `.desktop` launchers to start saved apps (through `uwsm app`; a saved command line is never run, so a terminal reopens as a plain terminal), reads `hyprctl` output with a size and time limit; autostart is off for every newly saved App Preset; switching it on keeps a private copy of the layout the page shows in `~/.local/state/ubruckhaus.simple-tile/autostart.json` (folder `0700`, file `0600`, shared with Workspace Presets), and at login only that copy is restored, by Theme Manager on its own or by Workspace Presets while it is on the bar, so the store never decides which apps start, and keeps its lock and per-session autostart marker in `$XDG_RUNTIME_DIR`. Switching a workspace between Native, Floating and Scrolling (Omarchy 4.5 and later) writes Omarchy's own per-workspace file `~/.local/state/omarchy/workspace-layouts/<workspace>.lua` atomically, as Super + L does: one line `o.workspace_mode({ workspace = "<n>", mode = "<mode>" })` with a checked number and one of the known modes (the folder must be yours), removed again when the workspace returns to the default mode. While the Workspace Presets plugin is on the bar, a change on the Workspaces or App Presets tab rewrites only that plugin's workspace keys in its own bar entry in `~/.config/omarchy/shell.json` (atomically, keeping the file's mode, under the same lock the plugin uses); no other part of `shell.json` is changed. Nothing goes over the network.
- **Ask AI** is off until you turn it on, and runs only when you click **Ask** or **Refine**. It starts one coding agent that is already installed and signed in, as an argv subprocess without a shell, in a new empty private folder (`0700`), with its own process group, a time limit, a hard size limit on every file it writes (`RLIMIT_FSIZE`, 256 MiB) and its private folder checked against 64 MiB, its answer read up to 256 KiB: Claude Code without tools (`--tools ""`, hooks off, no MCP servers, no session saved), Codex in its read-only sandbox, pi without tools, MCP servers, extensions or context files, Hermes with only its in-memory task list. Codex can read files, so it runs inside a bubblewrap jail (`bwrap`) that shows it no home folder except its own config folder, and that only through an overlay whose writes land in the private folder and are deleted after the Ask (nothing it writes there, such as config, hooks, plugins or MCP servers, outlives the Ask; only its sign-in file `~/.codex/auth.json` is written through, so a refreshed token stays); the jail's `/tmp` and empty home are each limited to 64 MiB, and it gets no session bus (no keyring, no portals). Antigravity is not offered in this version: its sign-in lives in the keyring, and the jail would have to open the whole keyring to it. Whether an agent is signed in is judged only by whether its credentials file exists or its API key variable is set; their content is never read. What is sent: your words, the names and main colors of your installed themes, the omarchy.org theme names and your installed font names; never files, paths, wallpapers, screenshots, window titles or settings. The answer is treated as data: only installed or catalog themes, known color keys as `#rrggbb`, installed fonts and a plain search phrase (looked up on Wallhaven under the rules above) are kept. **Local models:** the models pi lists on a loopback address (`127.0.0.1`, `localhost`, `::1`) run with `--offline`. Such a server is used only when every socket listening on its port belongs to you or to a system service (owners asked from the kernel over netlink `sock_diag`, as `ss` does, for IPv4 and IPv6; the list counts only when the kernel marks its end); if that cannot be shown, or another person's account listens there, the port is not used, neither for the agent nor for any request. If such a model's server is not answering, Theme Manager starts the user unit `llama-server.service` (port 8080) or `ollama.service` (port 11434) with `systemctl --user start` (service management, nothing else; the unit is never stopped). To give GPU memory back, it unloads only a model that one of its own asks loaded (a model that was already loaded is never touched): `POST /models/unload` on the llama.cpp router or `keep_alive: 0` on Ollama, loopback only (every request to such a server has one 3 s deadline and a 1 MiB reply cap), when the popup closes, the helper changes, Ask AI is left or Theme Manager ends. **Dictation:** the microphone only runs `omarchy-dictation toggle` (argv, no shell) and keeps no recording state; Theme Manager records nothing itself, and whether speech is recognised on this PC or by a cloud service is that backend's own setting. The Maprisma note's button opens a fixed marketplace address with `omarchy-launch-browser`.
- Clipboard paste uses `wl-paste`: image data (type checked by its magic bytes), or local file paths a file manager copied (image files only, at most 10, 50 MiB each). Drops accept the same, plus the image bytes a browser offers for a dragged picture (read with a 50 MiB cap and a 30 s deadline; the type comes from the bytes, never from the offered name). Nothing dropped or pasted is downloaded, executed or opened.
- Images are never decoded on trust: before any wallpaper, preview or thumbnail is shown or imported, its header is read (without decoding pixels) and anything over 16384 px per side or 64 megapixels in total (width × height × frames, for animated GIF/WebP) is refused, so a small, highly compressed file cannot declare a canvas that exhausts memory. Decoding runs on worker threads at thumbnail size, never on the UI thread.
- PNG metadata is bounded too: a PNG with more than 32 text chunks or more than 32 KiB of compressed metadata (zTXt, compressed iTXt, iCCP) is refused everywhere it would be shown or handed to the desktop, because the shell's image reader inflates all text chunks before the pixels. Imported PNGs are stored with only pixel, palette and colour chunks; text, EXIF and unknown chunks are dropped (pixels are copied byte for byte, not re-encoded).
- Text pasted into the two search fields, the theme name, the color fields, and the hex field and number fields inside GTK's color picker is read with `wl-paste` (at most 4 KiB, 2 s deadline, control characters flattened, 200 characters kept) instead of GTK's built-in paste, which would buffer whatever another app offers with no limit. Middle-click (primary selection) paste is turned off in the popup, and none of these fields takes text drops.
- For **Corners** it reads `hyprctl getoption decoration:rounding` (bounded) and, for the tooltip only, looks for an uncommented `rounding = N` in the current theme's `hyprland.lua` and `~/.config/hypr/looknfeel.lua` (at most 256 KiB each, symlinks refused, never executed).
- Remembers the popup position and size, and the settings, in `~/.config/omarchy/theme-manager/settings.json`; favorites, recently used themes, workspace wallpapers, workspace themes and presets in adjacent JSON files. Workspace wallpapers are stored by file name and only ever resolve to a visible wallpaper the theme already lists. Short-lived automation state (the background to return to, the last slideshow step) lives in `~/.cache/theme-manager/auto-state.json`.
- Custom themes are written as a new folder in `~/.config/omarchy/themes/` (never into an existing one): `colors.toml` with only `#rrggbb` colors (and the base theme's other color values, kept as they were), `icons.theme` (one icon theme name, checked), copies of the visible wallpapers (bounded copies, oversized images skipped), a `preview.png` drawn with GdkPixbuf, and `theme-manager.json` (base theme, font). Nothing that runs code is copied: no `.lua`, no terminal or editor configs. Only themes with that note, and not from git, can be edited again. Fonts are listed with `omarchy-font-list`, read with `omarchy-font-current` and set with `omarchy-font-set`, and only a font from that list is ever passed on (it edits config files with sed). The font you had before is remembered as `own_font` in `settings.json`. **Font & effects** stores per theme only a font name (checked as a name; only fonts from `omarchy font list` are ever set, and a saved font that was uninstalled later is kept but not applied) and one of `opaque`, `transparent`, `glassy` in `~/.config/omarchy/theme-manager/looks.json` (`0600`, bounded, checked on every read); the window style is set only through Omarchy's own `omarchy-hyprland-window-transparency <mode>` (argv, no shell), which writes Omarchy's own toggle and terminal glass under Omarchy's theme lock. The window style you had before is remembered as `own_windows` in `settings.json`.
- Deleting moves the theme or wallpaper into the freedesktop trash, `~/.local/share/Trash/` (`files/` and a `.trashinfo` in `info/`, created exclusively, mode 0600); Undo moves it back only if nothing has taken its place. Symlinks are just unlinked. If the trash is on another filesystem, the item is deleted as before.
- Previews call `omarchy-shell -q background set <image>` (Omarchy's own background IPC) and set the real background back the same way; the background link is never changed by a preview. Web previews download the full image from `w.wallhaven.cc` under the same rules as adding it, and keep at most the last three in `~/.cache/theme-manager/wallhaven/preview/`.
- Keyboard shortcuts (only when you set one): writes `~/.config/hypr/theme-manager-shortcuts.lua` (`o.bind` lines whose commands are this plugin's own `theme-toggle` or `theme_auto.py` with fixed arguments, paths checked to contain no shell characters) and one marked `require` line in `hyprland.lua`. It reads `hyprctl binds` and your `~/.config/hypr/*.lua` (size-capped) to colour the keys, and runs `hyprctl reload`, `hyprctl configerrors`, and `hyprctl dispatch`/`eval` for the capture submap.
- The bar widget runs `/usr/bin/python3 theme_auto.py` with fixed arguments (a workspace number, `tick`, `bg next|prev`, `theme next|prev`, `apply <slug>` with the slug checked again, `menu`), one at a time; a theme's key runs the same `apply`. It reads the focused workspace from Quickshell's Hyprland integration; `theme_auto.py` asks Hyprland's IPC socket for `activeworkspace` (read-only, size-capped).
- PID file lives in `$XDG_RUNTIME_DIR` (or a private 0700 fallback); signals are only sent after full process identity checks (uid, interpreter, exact script path, kernel start time).
